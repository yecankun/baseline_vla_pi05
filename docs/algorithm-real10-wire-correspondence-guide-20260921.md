# Real10：固定四点血管参照 + 6窗导丝点标

本轮只准备人审入口，不训练。目的是先检查能否从模糊原图中建立可靠的导丝对应，
再决定怎样监督“沿管推进”和“横向移动/形变”。不把像素光流当作导丝推进真值。

## 范围与入口

固定窗口 **#4、#39、#62、#65、#77、#100**，不扩展到175个宏请求，也不修改现有响应类别。
每窗Side/Top各看首末帧，合计24张导丝必看图；中间关键帧12张选填。其余帧可回放。
Side与Top共享事件窗口，拍摄时间各自记录；可见性和坐标分别填写，不能互相补造。

用户明确相机和血管在本批画面中稳定不动。血管参照因此改为每视角只标一次四点，
不再逐帧重复A/B。四点表示粗略分支路径，不是旧版任意血管纹理特征的重命名。

新入口：`tools/review_real10_wire_correspondence.py`。
默认页面：`http://127.0.0.1:8794`，仅本机回环服务，不连接相机或机械臂。
图像只读自本机`collected_data`。使用原始1920×1080 PNG，不读取224px模型图像。

## 操作顺序

1. 进入“1 · 血管四点”，选择能看清血管的窗口/帧。Side、Top分别点：
   **P0共同主干起点、P1分叉前且仍在共同主干内、PL左支内一点、PR右支内一点**。
   尽量放在管腔中央；左/右是实际任务分支，不是画面左右。每路四点，共八点。
   该模式允许在任一上下文帧定位，记录各点的来源图；不要求两路像素坐标一致。
2. 核对四点与固定血管画面一致，按实际核对情况勾选每路确认框，填写标注人，点击
   “保存固定血管四点”。它们全局复用，可切帧/切窗检查叠加。相机或血管改变位置时
   不要沿用本参照；不能将不同布置混成同一模板。
3. 切到“2 · 导丝 W”。每路选跟踪对象，优先同一导丝尖端；若用导丝段，必须是可跨帧
   辨认的**同一材料特征点**，填写说明。轮廓交点、最亮点、折弯位置不保证是材料点。
4. 每窗首末帧各只点W，中间关键帧选填。固定血管路径只读叠加，不再逐帧点血管。
   看不清时选“可见但无法定位”或“不可见/无可靠特征”，保留`xy=null`，不是零或静止。
5. 核对首末同一导丝点后，勾选对应视角的确认框，点击“保存本窗口导丝”或
   “保存并到下一窗口”。导丝确认与血管确认独立，修改点位后对应确认取消。
6. 两种模式可切换且保留草稿，但保存分别进行。任一模式未保存会阻止切窗；切帧不丢
   草稿。关闭/刷新前保存。“全图/局部、1:1/2倍”仅改变显示，坐标仍为原图像素。

已有“推进/未推进”结论仅在折叠说明内只读显示，不用重新选类别；尤其#65的下移不等于
推进，#100的小幅推进也不因为像素变化小就改成静止。本工具不自行复核或推断这些结论。

## 保存与边界

新版人审写入位置（均追加版本）：

```text
simulation_output/real10_wire_correspondence_v1/vessel_reference.jsonl
simulation_output/real10_wire_correspondence_v1/annotations_v2.jsonl
```

四点schema为`real10_static_vessel_four_point_v1`，每次保存一份全局双视角版本；
导丝schema为`real10_sparse_wire_correspondence_v2`，每次保存一份窗口双视角版本。
均不覆盖旧版本；多页面保存分别检查revision。
既有`annotations_joint_v2.jsonl`、旧监督包、原图、数据/动作标签和PI05权重均不写入。
准备入口只生成manifest与入口快照，**不创建伪人工标注**；未填写的点保持unreviewed/null。

如果旧`annotations.jsonl`存在，仅只读继承W坐标、身份和人工同点确认；新保存写v2文件。
旧A/B全部保留在原文件，不会自动变成四点。旧manifest/入口快照保留历史；本次页面协议
由当前代码及`interface_protocol_v2.json`说明，不修改旧manifest语义。

- 固定参照：每路四点、各点来源case/frame/path、原图坐标或null、说明、人工确认。
- 每窗导丝：身份类型/说明、同点确认、首中末W坐标/可见性、保存时的参照revision。
- reviewer、追加时间、revision；独立诊断且`policy_input_allowed=false`。

“已看帧”只统计导丝状态是否审阅；“同点对”只统计首末W可定位、身份合理且人工确认。
血管八点和两路确认另计。这些进度不表示路径投影有效或推进量已有验证。

**暂不自动导出推进量/阈值或拟合模型。** `P0→P1→PL`与`P0→P1→PR`只是粗略二维折线，
P1在分叉前而非真实分叉点，不能据此宣称精确中心线。以后计算需处理弯曲/分叉与遮挡，
不能直接换算毫米、三维伸长、contact/tactile或成功率。6个已开发案例不是独立验证集。

## 启动、停止与读取进度

准备包已存在时**不要再跑`--prepare`**。本机PowerShell，从项目根目录启动：

```powershell
.\.venv\Scripts\python.exe -B -u tools/review_real10_wire_correspondence.py --port 8794
```

打开页面标注；终端Ctrl+C停止，已经保存的追加记录保留。下次同命令继续。
若端口被占用，先确认是否已有本入口，复用它；不要结束未知进程。

只读查看进度（不创建标注）：

```powershell
.\.venv\Scripts\python.exe -B tools/review_real10_wire_correspondence.py --summary
```

点标完成后只需同步这两个小JSONL到4090；不再上传原图。后续算法侧先审查点对与缺失情况，
再提出跟踪/投影诊断，不自动开始新训练。
